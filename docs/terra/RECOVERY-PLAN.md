# WearWise 可用性恢复与数据方案

日期：2026-11-05。状态：2026-11-06 用户明确选择“由我直接修到可正常测试，再把代码上传 GitHub”。恢复原核心范围；保留现有数据库、不扩展云服务。

## 结论与当前故障

用户在先前交付的开发启动入口遇到“无法读取衣橱”，无法查看示例。先前生产构建测试通过不能代表实际交付启动方式可用，当前用户路径验收应重新打开。

本轮用正式 Google Chrome 的全新隔离 context 访问正在运行的 http://127.0.0.1:3000，选择体验示例衣橱并进入我的衣橱，实际得到：页面提示无法读取、卡片0张；通过浏览器原生 IndexedDB 只读查询，wearwise-demo-v1 的 garments 表已有8条。该证据只针对隔离测试库，未读取或修改用户个人浏览器数据。

项目已有 Dexie + IndexedDB，已有 garment/media/outfits/feedback/meta 表、8件示例种子和本地示例插画。当前症状不是缺少数据库或未准备种子。

高置信待验证假设：组件 useMemo 创建服务，effect cleanup 调用 dispose→db.close()，开发模式额外执行 setup/cleanup 后复用已关闭的服务。Dexie 默认 close 会禁止自动重开。涉及 composition/index.ts、wardrobe-page.tsx、wardrobe-count.tsx、recommendations-page.tsx。还需排除 schema/迁移异常等其他原因；不能未经错误追踪便将假设记为根因。

此前 playwright.config.ts 启动 npm run start；用户得到的命令却是 npm run dev，未覆盖开发模式，是已经确认的交付验证缺口。

## 数据库选择

1. 首选恢复阶段：保留已有 Dexie/IndexedDB。修复连接生命周期及启动流程，恢复8件示例与真实衣橱，不加新的基础设施。适合当前浏览器本地版；清站点数据会丢失的限制仍存在。
2. 可选个人长期使用版：用户若要求数据存到电脑文件、统一备份，可另批准 SQLite + 本地 Node API。浏览器经 API 访问，不能直接连接电脑数据库；主库迁移到服务端后，静态 Pages 无法承载相同主库，需要明确保留为演示版。照片独立文件存储时需临时文件、原子提交、孤立文件清理与一致备份机制，不能只替换数据库驱动。
3. 可选多设备/多人版：Postgres/Supabase，增加认证、用户隔离、对象存储、访问规则、配额和备份恢复；属于另一个范围，不用于修当前故障。托管费用、网络、账户及数据流向另核实，当前未安装或实测。

不建议为当前症状先安装 MySQL、Redis 或完整 Supabase。是否选 SQLite 取决于需要本机文件持久化，是否选 Supabase 取决于需要账号及跨设备共享，不取决于现有页面报错。

## Terra 任务顺序与架构要求

### P0：恢复实际入口（先做）

- 保持真实/示例库隔离；保护已有用户数据，不清库、不 reset、不自动重新播种到真实库。
- 为存储错误记录脱敏 code、operation、mode、schemaVersion，区分连接已关、迁移失败、校验失败和额度问题；不记录衣物内容、照片或密钥。
- 增加可复现的 dev 模式回归，捕获真实错误类型，先红后绿。
- 对服务及数据库实施一致的生命周期：浏览器同一模式的数据库由应用层管理，页面只释放订阅/取消自身请求，不关闭其他活跃消费者持有的连接；连接创建不得出现在服务端。应用层重建或数据库升级有明确关闭/打开边界。
- 同时核对开发热更新、StrictMode重复effect、路由切换与模式切换。不要通过关闭StrictMode、吞错返回空列表或删除测试掩盖故障。
- 提供使用者专用稳定启动入口：构建/启动/就绪检测/打开正式Chrome，固定origin；遇端口占用报告真实地址，不默默换端口造成“数据不见了”。原有 dev 命令仍须可用。

### P1：基础数据与展示（恢复后做）

- 保留现有五类衣物、四档保暖和两类风格，不把扩展内容混成必须的新产品范围。
- 将8件示例与图片整理成可审阅、版本化的种子清单；字段与真实衣物走相同校验、seed幂等、重置原子化且只针对demo库。
- 可提议扩到20–30件，覆盖温度档、连衣裙路线、外套不足、排除衣物等场景；这是待确认内容扩展，8件完整可用先验收。
- 展示素材使用已授权或原创图片，记录来源/作者/许可证；不批量抓取电商照片或把他人项目的代码许可当作图片授权。
- 样例气象明确example；衣物类别和规则来自结构化配置，不安装向量数据库或爬取大规模时尚语料。

### P2：个人可持续使用（新增范围，需确认）

优先补导出/导入备份，覆盖衣物、图片、推荐、反馈和schema版本；导入前校验、冲突预览、失败回滚。若选择SQLite，则先设计迁移预览和双份校验，保留原IndexedDB，只在用户确认迁移成功后改变主数据源。禁止无确认删除旧库。

本轮不包含自动AI、云账号或公开发布。真实模型继续沿用独立授权与样本验收。

## 验收关卡

G1 实际打开即可用：全新Chrome context点击示例，出现8件；使用者实际入口、npm run dev、生产启动分别验证；初次打开、刷新、路由切换、模式来回、服务重启和浏览器重开均能读取。记录模式/命令/地址/构建身份，不只贴测试数量。

G2 数据保留：已有测试衣物与照片在升级/重启后不变；真实和示例隔离，真实库没有播种或清空；迁移失败可恢复。

G3 完整闭环：实际录入3件衣物→天气（真实与主动示例分开验证）→生成→反馈→刷新，全部在最终交付入口走通；故障提示可重试且不能假装保存成功。

G4 可诊断：人为关闭连接、构造旧版本测试库、拒绝存储时都有正确错误和恢复路径；保留红→绿证据。

G5 用户验收：让用户按最终启动说明亲自打开并看到示例；在完成前只称修复候选，不称用户已可用。备份功能或SQLite迁移各有独立关卡，不拿P0通过当整个长期使用版完成。
