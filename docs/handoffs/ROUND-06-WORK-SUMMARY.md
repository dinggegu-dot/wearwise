# 第 6 轮工作说明｜04 穿搭灵感

更新：2026-11-23。代码在 [PR #37](https://github.com/dinggegu-dot/wearwise/pull/37)，接在第 5 轮 [PR #35](https://github.com/dinggegu-dot/wearwise/pull/35) 后面；目前都是待合并的分支，**不是正式网站已上线的功能**。详细技术记录见 [ROUND-06.md](ROUND-06.md)。

## 这一轮做了什么

把「穿搭灵感」从页面框架做成了能用的完整流程：用户上传穿搭照片，网站自动请求第 3 轮接好的 OpenRouter 灵感分析；AI 返回名称、配色、风格、版型、层次、场景等标签和分析文字。用户可以删掉不对的标签、添加自己的标签，修改名称和分析，确认后才保存。灵感列表可以看图、看摘要，也能查看、编辑和删除。

分析时会显示等待状态，不能提前保存；分析失败会留住照片，用户可以重试、换图或取消。换图或离开页面后，旧请求即使晚返回，也不会把新结果盖掉。灵感图片保存后会一直留在浏览器数据库中，直到用户主动删除；图里的衣服不会自动进入衣橱。

保存后，网站会从**用户最终确认的分析文字**里找明确表达的「喜欢／不喜欢」，放进「我的偏好 → 灵感归纳」。例如用户写「我喜欢灰白配色，但不喜欢紧身裤」，会得到两条归纳；只写「照片里是灰色上衣」不会被当成个人喜好。多张照片支持同一条喜好时会合并来源。修改或删除灵感后，归纳会重新核对：还有其他照片支持的留下，没有依据的自动归纳移除；用户自己改过或删过的归纳不会被自动覆盖或恢复。

推荐功能已经通过现有数据服务读取这些有效归纳，并受「是否考虑过往记忆与偏好」开关控制；不会再把整张灵感照片或原始分析文字当成第二份偏好重复输入。第 7 轮仍要完成「我的偏好」的可见管理页面。

## 怎么验证的

- **真实 AI 流程**：在调整后的页面上传真实穿搭照片，实际调用 `qwen/qwen3.8-max-0902`，接口返回 HTTP 200，耗时 **18,478 毫秒**。AI 给出 7 个标签，覆盖配色、风格、版型、层次、场景。用户修改分析并保存、刷新后，隔离测试浏览器里有 **1 条灵感、1 张图片、2 条有效归纳**。结构化记录和截图在 [round06-evidence](round06-evidence/) 目录。
- **自动化回归**：单元测试 **205 通过、1 跳过**；完整浏览器测试 **54/54 通过**；类型检查和生产构建通过。分析失败、重试、换图、离页、重复保存、数据刷新等页面测试也已覆盖。
- **测试边界**：页面自动化里的故障是模拟的，不能算真实 OpenRouter 故障。真实模型成功流程已经在调整后的 UI 上重新验证；本轮没有人为触发真实认证失败或超时。浏览器测试使用独立环境，没有改动用户日常衣橱数据。

## 现在还需要团队做什么

- 第 7 轮 02 完成「我的偏好」页面，让用户看见并管理明确偏好、灵感归纳和永久反馈。入口和检查项见 [第 7 轮开工交接](ROUND-07-START.md)。
- 正式网站仍需团队部署受保护的 Node 服务，把 OpenRouter 密钥只放服务端，并设置访问权限和调用限额。当前 PR 的本地成功结果不等于 GitHub Pages 已能调用 AI。
- 灵感归纳故意保守，只识别分析文字中清楚写出的喜好；复杂说法或所有同义改写未必能自动合并。不要把照片标签直接当作个人偏好。
