# M03：衣橱分类录入与弹窗居中

任务：#13。当前阶段：中期前的小幅完善。基线：PR #22 / `2f411d2f8eace340762f65006a4f35e0ffe076aa`，上游依赖 PR #21。代码基于共享候选，不另建应用。

## 问题与改后行为

1. 原版在“鞋履”分类点击添加仍默认“上衣”；不更改类别就保存，当前分类看不到该记录，切到全部能找到。它是录入与筛选的衔接问题，数据没有丢失。现在新增默认沿用当前分类，全部下仍默认上衣；保存时主动改了类别，分类视图跟随保存类别，全部视图保持全部。失败或取消不会切换分类。
2. 原版添加/编辑弹窗受 margin:0 影响停在屏幕左上角。现在只在衣橱 dialog 补 margin:auto，沿用原宽度、最大高度、内部滚动、焦点与取消逻辑。桌面与小屏幕均居中。

修改范围：`src/modules/wardrobe/ui/wardrobe-page.tsx`，以及03交接与脱敏文本证据。基于#22的产品差异为4行新增、2行删除。没有改数据库、AI、推荐算法、公共样式、依赖或07独立套件；06的照片预览和取消选图保护保留。

## 启动与复查

沿用仓库：Node>=22.12；`npm ci --legacy-peer-deps`；`npm run preview`。正式Google Chrome打开 `http://127.0.0.1:3000`。Windows若npm缓存落在受保护目录，可仅本次安装指定 `--cache "%LOCALAPPDATA%\npm-cache"`，不必改全局配置。

1. 真实衣橱→鞋履→添加，核对默认类别和弹窗居中；取消后不产生记录。
2. 从鞋履新增时主动选择外套并填写合法名称/颜色，确认后外套列表立即可见；全部视图录入仍保持全部。
3. 编辑选图、取消Windows选图窗口、重选、表单取消/Esc、确认保存与刷新；小屏幕可在弹窗内滚到确认按钮。
4. 排除/恢复、删除取消/确认，并确认其他衣物不受影响。
