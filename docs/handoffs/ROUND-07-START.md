## 一句话说清交接

第 6 轮已经把照片上传、AI 分析、用户确认、灵感保存和「灵感归纳」数据写通了。第 7 轮要做的是「我的偏好」页面，让用户管理已经保存的长期记录，不用重做灵感识图或数据库。

## 你能直接使用什么

| 已有内容 | 位置和用法 |
| --- | --- |
| 灵感和图片 | `createServices(mode).inspiration.list()` 读取灵感，`image(imageId)` 读图。第 7 轮偏好页一般不需要显示灵感原图。 |
| 三组长期偏好 | `createServices(mode).preferences.listActive()` 读取全部有效记录；传 `'explicit'`、`'inspiration'`、`'feedback'` 可分组。 |
| 新增明确偏好 | `preferences.addExplicit(content, requestId)`；取消或保存失败时不能出现新条目。 |
| 修改或删除偏好 | `preferences.edit(id, patch, revision)`、`preferences.remove(id)`；编辑时传当前 `revision`，冲突后应提示刷新或重试，不能覆盖别人刚保存的内容。 |
| 灵感归纳的保护 | 灵感改变后，第 6 轮会重新核对归纳来源。手动修改的归纳保留用户内容；主动删除的归纳留删除标记，不会因旧灵感再次分析而自己回来。页面只展示有效记录即可。 |
| 永久反馈数据 | 记录在 `group='feedback'`，带当时评价的搭配快照。第 7 轮用测试反馈记录验收页面；用户从推荐页提交真实永久反馈的入口属于第 8 轮。 |

服务定义见 `src/modules/preferences/index.ts`、`src/modules/inspiration/index.ts`，数据接口说明见 `docs/project/ROUND-02-DATA-API.md`。以当前代码中的 Schema 为准，不要另建偏好表。第 6 轮实际逻辑见 `src/modules/inspiration/ui/inspiration-page.tsx` 和 `src/modules/inspiration/summaries.ts`。

## 第 7 轮要完成的页面

1. 「我的偏好」分成 **明确偏好、灵感归纳、永久反馈** 三块。三块按来源展示，没有谁天然更优先，也不用新增偏好冲突确认流程。页面说明这些长期记录只在开启「考虑过往记忆与偏好」时用于后续推荐。
2. 明确偏好：能添加、编辑、取消编辑、删除；保存成功才更新，刷新后还在。
3. 灵感归纳：标明「根据穿搭灵感归纳」，能编辑和删除；**不显示具体来源照片或链接**。编辑或删除之后，再改动源灵感，也不能把用户的选择覆盖或恢复。
4. 永久反馈：能查看评价、原因和**当时被评价的搭配缩略图**，也能修改和删除。缩略图不能随着当前推荐搭配变化。第 7 轮可用测试数据验收；真实反馈入口由第 8 轮接。
5. 所有修改和删除完成后，后续读取必须使用最新有效记录。取消、保存失败、刷新恢复都要检查。

以上是 `docs/project/ROUND-SCHEDULE.md` 的第 7 轮范围，也要对照团队最新版《WearWise 网页功能概述》中的「我的偏好」和 `docs/project/RECOMMENDATION-MEMORY-RULES.md`。仓库内 `docs/project/WEB-FUNCTION-OVERVIEW.md` 可能还未同步用户在 2026-11-22 更新的版本；发现差异时先核对新版，不能自行省略需求。

## 建议的验收顺序

1. 用第 6 轮已确认的灵感，验证归纳是否出现在「灵感归纳」区域；客观描述的灵感不应凭空产生「喜欢」。
2. 对三组记录分别检查查看、编辑、取消、删除、刷新。重点试灵感归纳手改/删除后，再改源灵感，确认手改未被覆盖、删除未自动恢复。
3. 用测试反馈记录确认永久反馈的搭配缩略图是保存当时的快照。检查长期记录更新后推荐读取最新内容；记忆开关关闭时，旧的长期记录不作为新轮推荐条件。
4. 运行相关自动化测试、类型检查、生产构建，记录真实结果与未测边界。不要把测试替身说成真实 AI 调用。
