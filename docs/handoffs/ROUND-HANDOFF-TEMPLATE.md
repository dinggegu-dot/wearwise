# 第 __ 轮交接

| 项目 | 填写内容 |
| --- | --- |
| 负责人和接收者 | 岗位号、轮次、交接日期（北京时间） |
| 共同依据版本 | 功能概述、记忆规则、排班版本及本轮条目 |
| 唯一代码入口 | 仓库或离线交接包、分支、完整提交 SHA、依赖版本 |
| 本轮完成项 | 页面、按钮、流程、状态、兼容性 |
| 启动与配置 | Node、浏览器、安装和启动命令、`.env.example`、是否需要真实服务 |
| 下一轮调用入口 | 文件、服务或组件、输入／输出和错误示例 |
| 测试资料 | 可复用素材及许可、初始化方式、示例和真实数据隔离 |
| 实际验证 | 版本、环境、步骤、预期、实际结果、证据位置 |
| 已知问题 | 复现步骤、影响、是否阻碍接力、负责人 |
| 交接签收 | 接收者在自己电脑上的最短复验及结果 |

验证分别写 PASS、FAIL、NOT_RUN、BLOCKED 或 NOT_APPLICABLE。真实服务、模拟响应、作者自测和独立验收分别标记。

## 三条铁律的人工检查

1. 用有替代项的衣橱生成一次；修改草稿、换整套、换单件、切页或模拟失败均保留本轮。再次点“生成穿搭”并成功后才换轮。
2. 成功提交一条单次反馈，选择暂时不换，再连续调整。检查有效反馈始终参与且没有写入长期偏好。生成成功后确认旧单次反馈消失。保存失败的草稿不得参与。
3. 推荐页生成并提交单次反馈，去首页换整套或单件，再返回推荐页核对结果、条件、反馈与调整记录。反向调整同样检查。城市可以同步，推荐页已应用天气保持快照。

功能尚未接入时标记不可执行，并指明负责轮次。截图或纯界面观察不能证明模型输入已隔离；必要时核对服务输入或测试证据。
