## 现有代码与新规则不一致处的修改

| 旧行为 | 新规则 | 处理 |
| --- | --- | --- |
| 永久排除 `excludedPermanently` | 只有暂停加恢复日期 | 迁移为暂停且 `resumeOn: null`，用户可恢复或补设日期 |
| `excludedUntil` 时间戳 | 恢复日北京时间 00:00 | 迁移为不早于原时刻的北京日期 |
| 删除时物理删衣物和图片 | 旧搭配仍显示当时名称和图片 | 软删除，图片在任何快照引用期间保留 |
| 保存上传原图 `sourceImageId` | 只保留白底图 | 字段移除；旧原图仅在不被引用时清理 |
| 衣橱一变就清掉当前推荐 | 删除/暂停不改变已展示搭配，只提示 | 不再清除 `activeBatch`；旧推荐页恢复时也不再因衣橱修订号作废 |
| 天气无温度范围 | 依据快照含当天温度范围 | Open-Meteo 增加当日最低/最高温；示例天气 19–25°C |

## 文档歧义与本轮处理（已与 02 确认按新规则执行）

1. 旧版「永久排除」在新规则中没有对应，按上表迁移为无恢复日期的暂停。
2. 功能概述规定只保留白底图，但旧衣物有上传原图。新录入不再保存原图，旧原图在迁移时清理（仍被引用的保留）。
3. 推荐页要到第 8 轮重做。本轮服务层完全按新规则实现，旧推荐页只做兼容，未提前实现第 8 轮界面。
4. 新规则没有「风格」选项。新的数据结构使用四个开关；旧推荐页的风格仍保存在旧批次表里，第 8 轮替换。
5. 排班表的“测试入口”没有指定形式。本轮用自动化测试加可运行调用示例实现，没有新增网页。
6. 温度范围：本轮直接从 Open-Meteo 获取当日最低和最高温并写入快照。

## 04 的最短复验

1. 检出本分支的固定提交，运行 `npm ci --legacy-peer-deps`，再运行 `npx vitest run tests/round2`，应全部通过。
2. 阅读 `tests/round2/handoff-examples.test.ts` 中衣物与灵感的两个示例，确认输入、返回值、字段缺失和保存失败的表现能满足 AI 结果的保存需求。
3. 运行 `npm run preview`，在旧数据的浏览器档案中打开「我的衣橱」，确认衣物和图片都在；对一件衣物执行「暂时不推荐」和「恢复推荐」，刷新后核对状态。
