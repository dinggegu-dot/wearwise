## 开发模式故障及修复

原生产测试通过，但开发模式页面持有的服务在 React StrictMode effect cleanup 调用 db.close 后不能自动重开，示例库8条存在而界面读取失败。当前使用 close({disableAutoOpen:false})，保留连接清理且允许同一服务再次访问时重开；页面旧异步仍由已有取消/token约束。新增开发模式运行同一套业务测试，禁止通过关闭StrictMode、清库或吞错变空列表过关。

天气控件初始化前禁用请求按钮；Pages运行目标在next.config统一声明，以兼容已有Pages构建工作流。读取故障测试持续注入失败直到主动解除，避免StrictMode第二次读取自然成功掩盖故障。路由切换测试等待目标页出现再操作同名天气按钮。

## 启动与人工验收

环境 Node>=22.12，安装锁文件依赖 npm ci --legacy-peer-deps；该安装命令由接手者在自己的开发环境运行。

普通试用 npm run preview（构建并启动生产版）；开发 npm run dev。使用Chrome打开 http://127.0.0.1:3000，等待Ready再操作。同一origin保留浏览器数据，localhost与127.0.0.1不是同一份数据；清理站点数据可能丢失衣物。

1. 初次进入选择示例，打开我的衣橱看到8件，刷新仍在。
2. 推荐页主动使用示例天气、生成、反馈，刷新保持结果与反馈。
3. 切真实衣橱录入上衣/下装/鞋，照片随衣物保存；再次打开可读取。
4. 两种模式相互隔离，重置示例不影响真实数据。
5. 正式Chrome桌面/390px走闭环、320px不横向溢出；键盘可录入与反馈。
