# 真实衣物图片与穿搭平铺

推荐以衣橱里用户已确认的衣物为候选，按穿着关系组成一套平铺结果，单品名称、图片、理由和生成依据对应同一次结果。图片读取及展示与推荐选件由各自服务负责。后续实现以 [网页功能概述](WEB-FUNCTION-OVERVIEW.md) 和 [推荐依据与记忆规则](RECOMMENDATION-MEMORY-RULES.md) 为准。 [UI 示例](UI-REFERENCE.md)

## 基线与交付边界

第 1 轮候选仍可显示 0–2 套规则搭配，并通过 `services.wardrobe.image(imageId)` 读取本地 Blob。#22 已区分图片加载、缺图、失败和重试，避免错误图片或晚到结果覆盖当前展示。该能力和完整的单套平铺流程分别验收。 [第 1 轮交接](../handoffs/ROUND-01.md)

- 第 2 轮由 02 提供衣物图片及旧搭配快照的保存和读取。衣物后来被删除、暂停或换图时，旧搭配仍须能按当时的数据展示，并依规则提示已删除或已暂停；新候选应以最新可用衣橱为准。
- 第 3、5 轮由 04 提供图片处理服务、03 接入衣橱上传及确认。第 4、8 轮由 05 验证衣物 ID 与替换范围，完成推荐页平铺、单品清单与反馈。第 9 轮 06 复用组件到首页，使用首页自己的结果和调整状态。 [12 轮次排班](ROUND-SCHEDULE.md)

## 桌面验收

1. 用有许可且可区分的真实衣物图片核对 ID、名称、图像和搭配理由。验证缺图和读取失败状态。
2. 分别核对换单件和新生成整套。旧搭配中已删除或暂停的非目标件可以留在快照中，新的候选应排除仍不可用衣物。
3. 检查上下装与叠穿关系，保持照片比例和衣物外观。切页和刷新后按实际版本恢复，首页和推荐页调整不串状态。
4. 分开记录本地平铺、真实图片处理和推荐调用的证据，图片处理的外部服务按对应轮次的授权和样本范围验证。第 10、12 轮由 07 按固定 SHA 复验。
