# WearWise 推荐依据与记忆规则

版本基线为 2026-11-09 提供的《WearWise 推荐依据与记忆规则 修订版》。[Word 原件](source/WearWise%20%E6%8E%A8%E8%8D%90%E4%BE%9D%E6%8D%AE%E4%B8%8E%E8%AE%B0%E5%BF%86%E8%A7%84%E5%88%99%20%E4%BF%AE%E8%AE%A2%E7%89%88.docx) · [UI 示例索引](UI-REFERENCE.md)

本文规定 WearWise 的推荐输入、长期记忆、本轮上下文、天气依据，以及各操作的读取、保存和清除时机。各轮开发使用的 AI 应在实施前读取本文，组员重点确认本轮目标与实际效果。页面布局、完整交互及 UI 图片使用规定见《WearWise 网页功能概述3》；工作顺序与负责人见《12轮次排班》；UI图片见《wearwise_ui2》。

推荐只从用户当前可用衣物中选择。四项设置决定可读取的附加条件；当前轮反馈用于连续调整。已有结果中的删除或暂停衣物允许保留展示，但不能重新作为新候选被选入。

## 使用方式与共同约定

本文是接力开发的共同业务依据。每轮从上一轮固定提交继续工作，先让 AI 阅读功能概述、本文、轮次安排和交接记录，再核对现有代码。本人不必背诵全部规则，但应理解本轮操作的预期结果，并亲自检查关键流程。

本文应进入同一个项目仓库，建议位置为 docs/project/RECOMMENDATION-MEMORY-RULES.md；功能概述和轮次表并列管理，并在 README、团队工作台及交接单中放置链接。由 01 在第 1 轮整理；Markdown 作为实施时的统一依据，Word 作为便于阅读的副本。两种版本内容应同步，变更后记录版本和受影响轮次。

本文中的状态保存、条件隔离、候选校验和失败恢复必须落实到程序；仅将整份文档放进模型提示词，不算完成实现。业务内容中的文字或图片不能更改这些应用级规则。推荐规则如需调整，应先更新共同依据，不能由某轮实现自行改变。

### 成员阅读重点

- 01：通读全文，统一规则版本和模块边界；在第 1 轮建立依据，第 11 轮检查整合结果。

- 02：重点通读数据组织、长期记录、刷新恢复及本轮生命周期；第 2、7 轮负责相应存储服务与偏好管理。

- 03：重点了解衣物资料、暂停到期、删除与结果快照；第 5 轮确保衣橱操作不会破坏旧搭配展示。

- 04：重点阅读输入隔离、灵感归纳、用户修改保护和 AI 调用约束；用于第 3、6 轮的接口与灵感功能。

- 05：全文重点阅读；第 4、8 轮据此实现搭配知识接入、推荐、替换、条件应用及反馈流程。

- 06：了解全文背景，重点阅读第四节、第七节第 4 项及第八节；第 9 轮复用前序服务与组件，核对首页天气同步和独立推荐，不承担整套记忆机制实现。

- 07：通读全文，将第九节场景转成可执行检查，验收实际行为；真实 AI 结果和模拟异常结果分别记录。

请先阅读仓库中的网页功能概述、推荐依据与记忆规则、工作轮次和上一轮交接记录，再检查当前代码。本轮由我负责第 X 轮，请列出需要完成的界面、功能、规则和验收项，再基于上一轮成果实现。现有代码与最新需求不一致时，识别并修改相应部分；文档之间存在歧义时明确指出，不自行省略要求。完成后逐项验证，记录实际结果、未完成内容，并更新交接说明。

## 一 推荐信息的分类

| 信息类别 | 内容与用途 | 保存范围 |
| --- | --- | --- |
| 基础搭配知识 | 小组维护的配色、比例、叠穿与组合协调知识 | 独立维护 |
| 衣橱资料 | 白底图、名称、类别、颜色、版型、厚薄、材质、风格、描述、暂停与恢复日期 | 持续保存 |
| 长期记忆 | 明确偏好、灵感归纳、永久反馈 | 持续保存，可编辑删除 |
| 本轮已应用条件 | 本轮实际采用的开关、文字、参考图、场景及天气依据 | 本轮 |
| 本轮调整与反馈 | 换整套／单品记录、已成功提交的反馈 | 本轮 |
| 设置区草稿 | 左侧尚未点击生成应用的设置与保留内容 | 独立于本轮已应用条件 |
| 反馈草稿 | 尚未成功保存的评价、原因与适用范围 | 未提交状态 |

衣橱资料不属于个人偏好。关闭长期记忆开关后仍须读取衣橱，检查单品可用性。长期灵感图片保存在灵感库，确认后的总结进入“我的偏好”；临时参考图只作为本轮条件，不自动进入长期记忆。

### 基础搭配知识的维护与接入

基础搭配知识独立于本规则文档维护，建议放在 docs/knowledge/OUTFIT-TIPS.md，包含小组确认的配色、比例、叠穿、厚薄与场景搭配技巧。第 3 轮由 04 提供真实 AI 调用通道，第 4 轮由 05 整理技巧并接入推荐服务；生成、换整套、换单件和首页更换均通过服务读取适用知识。

技巧文件应记录版本和来源，修改后用于后续调用，不自动更改当前结果或用户偏好。基础知识不能绕过条件开关、暂停状态和衣橱可用性；天气或场景关闭时，不借通用技巧推定当前天气或用户场景。是否实际接入，应检查请求内容与测试结果，不能仅以文件存在作为完成证据。

## 二 数据组织与记录建议

以下记录用于区分已应用条件、未提交修改、衣物可用性和记忆来源，不限定数据库、模型或向量存储技术。

### 1 衣物与搭配结果

- 衣物使用稳定的唯一标识，关联当前资料、分类、暂停状态、恢复日期及是否已删除。

- 结果记录本套衣物标识、展示缩略图或结果快照、平铺图、推荐理由和生成依据。

- 反馈关联具体结果，防止更换结果后将旧反馈错绑到新搭配。旧结果快照可用于展示和回看，不作为当前衣物可用的证明。

参考 PNG：03-穿搭推荐-平铺搭配.png；05-我的偏好.png；03-5-当前搭配衣物状态提示.png

### 2 长期偏好与灵感来源

- 每条长期偏好记录标识、内容、所属组、有效状态及是否由用户手动修改。

- 灵感归纳在内部保留所依据的灵感标识，用于源图修改或删除后的核对；界面不展示来源缩略图和链接。

- 保留用户主动删除或手动修改的状态，避免后续归纳把相同内容自动恢复或覆盖。

- 永久反馈记录评价、明确原因和关联搭配信息，不将整套不喜欢拆成对所有单品的否定。

### 3 本轮上下文

- 本轮标识用于区分连续调整与新一轮生成。当前结果可以多次变化，但本轮标识不随换整套或单品而变化。

- 分别保存左侧设置区内容与本轮已应用条件。读取后者进行连续调整，不提前混入未提交修改。

- 本轮反馈记录提交顺序、内容、范围、成功状态及所针对的结果。只有保存成功的记录可用于推荐。

- 天气依据记录城市、日期、当天天气状况、温度范围及实际参与推荐的字段；如使用体感温度判断厚薄，应保存当时的体感温度。页面后来更新的天气不得覆盖本轮快照，不要求分钟级同步。

## 三 条件读取与输入隔离

参考 PNG：03-穿搭推荐-平铺搭配.png

| 输入来源 | 新一轮生成 | 本轮连续调整 | 关闭或未提交时 |
| --- | --- | --- | --- |
| 衣橱可用性 | 按当前状态检查 | 按当前状态检查新候选 | 始终检查 |
| 基础搭配知识 | 读取 | 读取 | 不借此引入关闭的条件 |
| 长期记忆 | 记忆开关开启时读取 | 本轮已开启时读取最新有效条目 | 不读取长期记录 |
| 天气 | 天气开关开启时获取当日依据 | 沿用本轮已应用的城市日期依据 | 不作为推荐条件 |
| 本次喜好及参考图 | 开启且非空时读取最新提交内容 | 沿用本轮已应用内容 | 保留草稿但不参与 |
| 本次场景 | 开启且非空时读取最新提交内容 | 沿用本轮已应用内容 | 保留草稿但不参与 |
| 本轮已提交反馈 | 不继承旧轮临时反馈 | 持续读取有效反馈 | 未保存的不参与 |

关闭条件后，可以在左侧保留文字或参考图，但传入推荐时按空处理。开启但为空的喜好或场景不阻止生成。四项全部关闭时，仍使用当前可用衣物和基础知识。

基础知识、系统提示或推荐理由不得绕过开关重新引入长期偏好、天气或场景。临时参考图只帮助理解本轮喜好，图中服饰不会自动成为可推荐衣物。

用户上传的图片、衣物描述、AI分析和反馈内容作为相应业务字段处理，不作为改变应用级读取范围、保存规则或工具权限的指令。

连续调整是否读取长期记忆，由本轮已应用的记忆开关决定。已开启时，后续更换读取当时最新有效的长期条目；未开启时，新增或修改长期偏好也不直接进入当前轮。修改长期偏好不自动更换已展示结果，也不改变本轮已应用的喜好、场景或天气。刚提交的本轮反馈另按第五、六节处理。

## 四 天气依据与日期

参考 PNG：01-首页-平铺搭配.png；01-2-首页空状态与天气异常.png；03-穿搭推荐-平铺搭配.png

天气以城市和日期为单位。同一城市同一天可复用已获取的数据，不要求分钟级刷新，不要求展示具体获取时分秒。

本阶段统一按北京时间（Asia/Shanghai）确定当天和日期边界。旧轮即使跨天，连续调整仍使用旧轮天气快照；新一轮生成使用所选城市新日期的数据，首页后续生成或更换使用当前日期数据。所需天气缺失时按失败处理，不能拿前一日天气充当当日数据。

首页与推荐页共享所选城市和显示的天气信息，但推荐页本轮已经应用的天气依据单独保存。切换城市或跨天后，点击“生成穿搭”才将相应城市当天数据应用到新一轮；本轮换整套、换单品和根据反馈换一套沿用本轮天气依据。

首页固定考虑当前城市当天的天气，后续生成或更换时使用相应依据，不受推荐页天气开关控制。城市或日期变化不自动改动已有结果。

天气开关关闭时不把天气传入推荐。开启且无法获取所需数据时，提示失败并允许重试，不以示例天气代替、不静默降级为忽略天气。生成未成功时保留旧结果和本轮反馈。

结果显示的生成依据取自实际使用的数据。例如“深圳 · 11月9日天气 · 上班 · 长期偏好”；未使用的条件不写入依据或理由。

## 五 长期记忆的写入与维护

参考 PNG：05-我的偏好.png

### 1 明确偏好

参考 PNG：05-2-添加与编辑偏好.png

由用户主动添加、编辑或删除。保存后作为明确偏好保留，取消或保存失败不写入。

### 2 灵感归纳

参考 PNG：04-2-灵感上传与编辑.png；05-我的偏好.png

根据用户确认保存后的灵感名称、标签和AI分析进行归纳，写入“我的偏好”的“灵感归纳”。AI分析可由用户直接改写，标签通过删除和添加修正；归纳以最终确认内容为依据，不默认用户喜欢图中所有元素。

后续推荐统一从“我的偏好”读取总结，不把灵感图片作为第二套独立偏好重复读取。未保存或分析失败的灵感不进入长期归纳。

源灵感修改或删除后，重新核对相关且未被手动修改的自动归纳：其他灵感仍支持的内容保留，失去依据的内容更新或移除。内部来源关联用于这项维护，不要求页面展示来源图。

独立设置或手动修改的偏好只接受用户对条目的直接编辑或删除，不能被重新归纳覆盖。主动删除的条目不因再次读取相同灵感而自动恢复。

### 3 永久反馈

参考 PNG：03-2-搭配反馈与无替代提示 .png；03-3-保存反馈后的弹窗.png；05-我的偏好.png

用户提交评价并选择“永久适用”，保存成功后写入长期永久反馈，并同时加入当前轮反馈。对当前轮而言，它是刚提交的明确要求；不受当前轮是否读取长期记忆的限制。后续新轮是否读取该长期记录由记忆开关决定。

未填写原因时只保存对该整套组合的态度，不推断为对全部衣物、颜色或风格的永久否定。

用户可以修改或删除长期记录。修改后长期推荐依据使用最新内容，删除后不继续作为长期推荐依据。

永久反馈的长期条目与本轮反馈副本保留对应关联。在“我的偏好”中成功修改或删除该条目时，同步更新或移除当前轮中对应的反馈副本，不影响其他反馈，也不自动改变当前搭配。保存失败时两处均保留原有效状态；本轮副本若已随新轮清除，无需重新建立。

### 4 三组内容的关系

明确偏好、灵感归纳和永久反馈按来源分组，不按来源自动分配优先级。采用长期记忆时三组有效内容均参与。本阶段不建立长期偏好内部冲突检测或确认流程。

## 六 本轮上下文与反馈生命周期

### 1 开始新一轮

参考 PNG：03-穿搭推荐-平铺搭配.png；03-4-推荐生成与异常状态.png

点击“生成穿搭”读取最新设置并请求生成。仅在生成成功后提交新轮状态：替换已应用条件和当前结果，清除旧轮的换整套／单品记录、单次反馈、旧轮用于调整的反馈记录及反馈草稿。

四个开关、左侧内容、城市、衣橱资料、暂停与恢复日期、灵感库和长期记忆继续保留。长期永久反馈的本轮临时副本可随旧轮清除，但其长期条目不删除。

生成失败不提交新轮，保留旧结果、已应用条件和有效反馈，允许重试。左侧最新输入继续作为设置区内容保留。

### 2 连续调整

参考 PNG：03-穿搭推荐-平铺搭配.png；03-3-保存反馈后的弹窗.png

换整套、换单品及“根据反馈换一套”不开始新轮，不清除本轮反馈。普通栏目切换和返回同样保留本轮状态。单纯更换不自动转成永久不喜欢，也不写入长期偏好。

连续调整读取本轮已经应用的喜好、参考图、场景和天气，以及已成功提交的有效反馈，不读取尚未点击生成应用的左侧修改。

### 刷新与重开后的恢复

在同一浏览器、同一站点中，刷新或重开后恢复当前搭配、本轮标识、已应用条件、有效反馈、调整记录及设置区内容；临时参考图作为本轮或草稿数据恢复，不进入灵感库。反馈草稿如被恢复，仍是未提交状态，不能直接影响推荐。

恢复时重新核对衣物删除及暂停状态，并显示旧搭配提示，不自动生成或换件。本轮已应用天气保留原快照，页面天气按当前城市和日期读取。新一轮生成成功后释放旧轮专用临时资料；设置区仍引用的图片继续保留，不能误删。

数据按浏览器和站点地址隔离。清理站点数据后不保证恢复；Git 交接不会自动携带上一人的浏览器衣橱和本轮状态。各轮应交付可复用的许可测试素材与初始化方法，不以私人浏览器数据作为下一轮依赖。

### 3 单次反馈与反馈草稿

参考 PNG：03-2-搭配反馈与无替代提示 .png；03-6-反馈保存失败.png

“仅适用于此次搭配”中的此次指整轮连续调整。该反馈保存成功后用于本轮所有后续更换，直至新一轮生成成功。它不写入长期记忆。

只打开反馈、填写但未提交、取消、关闭或保存失败，都不新增有效反馈。保存失败保留表单内容供重试，不显示“反馈已保存”。

### 4 本次要求的优先关系

本次明确喜好、场景及已提交反馈优先于长期记忆中与其不同的要求。同一轮后来提交的明确修正优先于之前与其冲突的要求，其他没有冲突的反馈继续保留。

例如长期偏好是休闲风，本次要求参加婚礼且正式一点，则按本次场景选择更正式的组合。该覆盖发生在本次推荐，不自动改写长期条目。

## 七 各操作的AI调用流程

### 1 新一轮生成

参考 PNG：03-穿搭推荐-平铺搭配.png；03-4-推荐生成与异常状态.png

- 读取左侧最新开关及内容，建立待应用条件；检查衣橱当前可用单品。

- 按开关读取长期记忆、当日天气及本次喜好／场景；不继承旧轮临时反馈。

- 让AI从可用单品中选择组合，再检查单品标识与可用性；衣物不足时说明缺少类别。

- 为同一组单品生成平铺展示、清单、理由和依据；验证实际结果与读取条件一致。

- 成功后替换本轮状态；失败则保留旧轮并提供重试。

### 2 换一套与根据反馈换一套

参考 PNG：03-穿搭推荐-平铺搭配.png；03-3-保存反馈后的弹窗.png；03-4-推荐生成与异常状态.png

读取本轮已应用条件和有效反馈，重新检查衣橱可用性，寻找与当前不同的整套组合。可以保留部分合适单品，但不得重新选入已删除或仍暂停的衣物。成功只更新本轮结果和调整记录；无其他组合则保留旧结果并说明。

### 3 换掉这件

参考 PNG：03-2-搭配反馈与无替代提示 .png；03-5-当前搭配衣物状态提示.png

确认目标单品位置，读取本轮条件与有效反馈，在保留其他位置的前提下选择当前可用替代。只更新目标位置及相关图、清单和理由；没有替代则说明并保留原结果。

若保留位置已有后来删除或暂停的衣物，继续保留这些位置并显示提示，不擅自更换，也不将其作为有效新候选重新选入。

### 4 首页推荐与更换

参考 PNG：01-首页-平铺搭配.png

固定读取长期记忆、当前城市当天的天气、当前可用衣物及基础知识，不读取推荐页四个开关、本次喜好、场景或单次反馈。首页更换不清除或继承推荐页的本轮记录。

### 5 反馈保存与结果展示

参考 PNG：03-3-保存反馈后的弹窗.png；03-6-反馈保存失败.png

先保存反馈，再显示成功弹窗。选择“根据反馈换一套”调用本轮整套调整；选择“暂时不换，返回”只关闭弹窗，保留结果。反馈保存失败时保留表单，重试成功前不把内容传入推荐。

## 八 衣物可用性与生成结果校验

参考 PNG：03-5-当前搭配衣物状态提示.png；03-4-推荐生成与异常状态.png

新生成整套及新替代单品必须是用户已保存、未删除且不在暂停期间的衣物。到期或提前恢复只恢复候选资格，不保证下次一定被使用。

暂停推荐的恢复日期按北京时间解释，自恢复日期当天 00:00 起恢复候选资格。页面读取和每次选取新候选时均重新判断，无需依赖浏览器在午夜持续运行；也可提前手动恢复。暂停状态与恢复日期单独保存，不因换搭、反馈或新一轮生成而清除。

已有搭配包含后来删除或暂停的衣物时，仅提示并保留画面。下一次生成新一套时完全排除；只换某一件时允许保留其他旧位置，但新选替代必须可用。

不能根据参考图、基础知识或AI补画增加用户没有的衣物。平铺图与清单须对应同一组单品，保留真实颜色、图案和款式，理由只引用实际使用的条件。

找不到替代或其他组合时明确说明，不把同一结果伪装成新结果。数据检查和生成失败均不能提前清空旧轮状态。

### 生成成功与提交时机

模型返回不等于生成成功。结果还须通过衣物 ID、候选可用性、目标替换范围及图文一致性检查，准备好必要的平铺展示数据，并成功保存结果和对应状态，才提交新轮或更换结果。新一轮成功时，结果替换与旧轮清除应作为一致的状态更新完成。

任一必要环节失败，包括模型、校验、必要图片准备或结果保存失败，均保留旧结果、已应用条件和有效反馈，并允许重试。更换失败不新增成功调整记录；已独立保存成功的反馈不因后续换搭失败而撤销。

平铺展示可使用用户确认的白底衣物图，按上下装与叠穿关系组合；不限定必须再次调用图片生成模型。无论实现方式如何，都须对应相同衣物 ID，保留真实颜色、图案和款式，不补造单品。

## 九 典型调用核对场景

| 场景 | 预期行为 |
| --- | --- |
| 四项开关全关闭 | 只用可用衣物和基础知识，不读取天气、长期偏好、喜好或场景 |
| 左侧改了场景但未点生成，随后换一套 | 仍用本轮已应用场景 |
| 改城市或跨天后未点生成，随后连续调整 | 沿用本轮已应用天气；成功点击生成才采用相应城市当天数据 |
| 提交单次“今天不想穿黑色”，连续换多次 | 整轮沿用，直到新一轮生成成功 |
| 反馈保存后选择暂时不换 | 结果不变，反馈已生效，后续更换使用 |
| 记忆开关关闭时提交永久反馈 | 本轮作为新反馈使用；以后按记忆开关决定是否读取长期记录 |
| 生成失败 | 旧结果、已应用条件与有效反馈保留 |
| 删除／暂停B后换A | 只换A，B保留并提示；下一次生成整套排除B |
| 删除灵感图但归纳还有其他依据 | 归纳继续保留 |
| 归纳被用户改写或主动删除 | 不由系统重算覆盖或自动恢复 |
| 只点击换一套或换掉这件 | 不自动写入永久不喜欢 |
| 只评价整套不喜欢，原因为空 | 只记录组合态度，不否定全部单品 |
| 刷新或同一浏览器重开 | 恢复结果、本轮条件、有效反馈和设置草稿；恢复的反馈草稿仍不生效。 |
| 本轮已开启记忆后修改长期偏好，再换一套 | 读取最新有效长期内容，保留本轮已应用的喜好、场景和天气。 |
| 本轮未开启记忆后新增长期偏好 | 当前轮更换不读取该长期条目；本轮刚提交反馈仍按反馈规则使用。 |
| 编辑或删除永久反馈条目 | 同步更新或移除当前轮对应副本，不改当前画面，不影响其他反馈。 |
| 恢复日期当天首次打开或生成 | 按北京时间判断资格已恢复，无需等待后台定时器。 |
| AI 返回后图片准备或结果保存失败 | 不提交新轮或更换结果，旧结果与有效反馈保留。 |
| 反馈已保存，但根据反馈换一套失败 | 反馈继续有效，当前搭配保留，可再次尝试更换。 |
| 更新基础搭配技巧文件 | 后续调用读取新版本；不自动改当前搭配或长期偏好。 |
| 首页更换，推荐页已有本轮反馈 | 首页不读取或清除该反馈，使用首页固定的长期记忆和当天天气依据。 |
